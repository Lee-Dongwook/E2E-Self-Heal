# Exit codes & JSON output

`--json` emits one machine-readable result to stdout; human output stays on stderr so CI can
parse it safely.

## Exit code contract

- `e2e-healer heal <path>` exits `0` when the test is healed and `1` for a refusal.
- `e2e-healer heal` (suite mode) exits `0` only when every discovered failing test is healed.
- `e2e-healer review` exits `0` after a completed review; wrappers branch on `has_findings`.

## JSON contract

Every result contains a `schema_version` and `kind` discriminator. Current output is schema
`"2.0"`: version 2 introduced the first-class `"refusal"` kind and its closed reason taxonomy.
Consumers must reject unsupported schema majors and unknown `kind` or refusal-reason values.
See the [schema versioning and deprecation policy](./schema-versioning) for the compatibility
and migration rules.

| Field | `RepairSummary` | `RefusalReport` | `SuiteSummary` | `ReviewReport` |
| --- | --- | --- | --- | --- |
| `schema_version` | `"2.0"` | `"2.0"` | `"2.0"` | `"2.0"` |
| `kind` | `"repair"` | `"refusal"` | `"suite"` | `"review"` |
| `test_script_path` | ✔ | ✔ | — | ✔ |
| `is_success` | ✔ | `false` | ✔ | — |
| `reason` | — | ✔ | — | — |
| `loop_count` | ✔ | ✔ | — | — |
| `instructions` | ✔ | — | — | — |
| `evidence` | ✔ | ✔ | — | — |
| `results` | — | — | ✔ (`RepairSummary` / `RefusalReport`) | — |
| `findings` | — | — | — | ✔ |

The `evidence` object records the parsed failure, failing selector, DOM diff context, a
content-hashed ARIA snapshot reference, ordered repair candidates, and ordered loop-stage
outcomes. Snapshot content is not embedded in output; its reference points to the original
workspace artifact as provenance when available. The digest is over the redacted extracted
snapshot, not the source `error-context.md` bytes. Sensitive structured values and URL query
values are redacted.

### Example: successful single-file heal

```json
{
  "schema_version": "2.0",
  "kind": "repair",
  "test_script_path": "tests/login.spec.ts",
  "is_success": true,
  "loop_count": 2,
  "instructions": [],
  "evidence": {
    "parsed_error": "Error: locator('#submit') timed out",
    "failing_selector": "#submit",
    "dom_diff_context": [],
    "aria_snapshot": null,
    "candidates": [],
    "loop_history": []
  }
}
```

### Example: single-file refusal

```json
{
  "schema_version": "2.0",
  "kind": "refusal",
  "test_script_path": "tests/login.spec.ts",
  "reason": "ambiguous_target",
  "is_success": false,
  "loop_count": 2,
  "evidence": {
    "parsed_error": "Error: locator('#submit') resolved to 2 elements",
    "failing_selector": "#submit",
    "dom_diff_context": [],
    "aria_snapshot": null,
    "candidates": [],
    "loop_history": []
  }
}
```

### Example: suite heal
The nested `evidence` values below are abbreviated; see the single-file examples above for the
complete evidence shape.

```json
{
  "schema_version": "2.0",
  "kind": "suite",
  "total_failed": 2,
  "healed": 1,
  "is_success": false,
  "results": [
    {
      "schema_version": "2.0",
      "kind": "repair",
      "test_script_path": "tests/login.spec.ts",
      "is_success": true,
      "loop_count": 1,
      "instructions": [],
      "evidence": {}
    },
    {
      "schema_version": "2.0",
      "kind": "refusal",
      "test_script_path": "tests/checkout.spec.ts",
      "reason": "insufficient_evidence",
      "is_success": false,
      "loop_count": 0,
      "evidence": {}
    }
  ]
}
```
